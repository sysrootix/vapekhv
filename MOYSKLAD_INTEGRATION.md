# Интеграция с МойСклад

## Обзор

Реализована полная интеграция с сервисом МойСклад для автоматической синхронизации каталога товаров.

## Возможности

- ✅ Автоматическая синхронизация категорий, товаров и вариантов
- ✅ Скачивание и локальное хранение изображений
- ✅ Синхронизация остатков и цен
- ✅ Автоматическое обновление каждые 30 минут
- ✅ Синхронизация при запуске сервера
- ✅ Поддержка модификаций (вариантов) товаров
- ✅ Раздача изображений с собственного сервера

## Изменения в базе данных

### Category
- `moySkladId` - UUID товарной группы из МойСклад
- `moySkladUpdated` - Время последнего обновления

### Product
- `moySkladId` - UUID товара из МойСклад
- `moySkladUpdated` - Время последнего обновления
- `article` - Артикул товара
- `code` - Код товара
- `externalCode` - Внешний код

### ProductVariant
- `moySkladId` - UUID модификации из МойСклад
- `moySkladUpdated` - Время последнего обновления

## Настройка

### 1. Получить токен МойСклад

1. Войдите в МойСклад
2. Перейдите в **Настройки → Пользователи и права**
3. Создайте нового пользователя или используйте существующего
4. В разделе **API** сгенерируйте токен доступа

### 2. Настроить переменные окружения

Добавьте в `.env` файл:

```env
MOYSKLAD_TOKEN=ваш_токен_доступа
```

### 3. Очистить тестовые данные

```bash
cd backend

# Применить миграции (если нужно)
npx prisma migrate dev

# Очистить тестовые данные
psql -U postgres -d vapekhv_db -f prisma/migrations/cleanup_test_data.sql

# Или через psql
psql -U postgres -d vapekhv_db
\i prisma/migrations/cleanup_test_data.sql
```

### 4. Установить зависимости

```bash
npm install
```

### 5. Запустить сервер

```bash
npm run build
npm start
```

При запуске автоматически начнется первоначальная синхронизация.

## Как работает синхронизация

### 1. Синхронизация категорий

- Получает все товарные группы (ProductFolder) из МойСклад
- Скачивает изображения категорий (если есть)
- Создает/обновляет записи в таблице `categories`
- Использует `moySkladId` для идентификации

### 2. Синхронизация товаров

- Получает все активные товары из МойСклад
- Получает остатки для каждого товара
- Скачивает все изображения товара
- Сохраняет изображения в `backend/uploads/products/`
- Создает/обновляет записи в таблице `products`

### 3. Синхронизация вариантов

- Получает модификации для каждого товара
- Синхронизирует характеристики (цвет, размер и т.д.)
- Обновляет цены и остатки для каждого варианта
- Создает/обновляет записи в таблице `product_variants`

### 4. Работа с изображениями

- Изображения скачиваются по публичным ссылкам из МойСклад
- Генерируется уникальное имя файла на основе MD5 хеша URL
- Изображения сохраняются в `backend/uploads/products/`
- Дубликаты не скачиваются повторно
- Фронтенд получает изображения по URL: `https://vapekhv.live/uploads/products/{filename}`

## Автоматическая синхронизация

Синхронизация происходит:

1. **При запуске сервера** - первоначальная синхронизация
2. **Каждые 30 минут** - автоматическое обновление через cron

Интервал синхронизации настраивается в `backend/src/config/moysklad.ts`:

```typescript
syncIntervalMinutes: 30, // Изменить на нужное значение
```

## API endpoints

### Изображения

Изображения доступны по адресу:

```
GET /uploads/products/{filename}
```

Пример:
```
https://vapekhv.live/uploads/products/a1b2c3d4e5f6.jpg
```

### Ручной запуск синхронизации (опционально)

Можно добавить endpoint для ручного запуска:

```typescript
// В backend/src/routes/admin.routes.ts
router.post('/sync', async (req, res) => {
  try {
    await syncService.syncCatalog();
    res.json({ success: true, message: 'Синхронизация запущена' });
  } catch (error) {
    res.status(500).json({ error: 'Ошибка синхронизации' });
  }
});
```

## Обработка ошибок

- При ошибке синхронизации сервер продолжает работу
- Ошибки логируются в `backend/logs/error.log`
- Следующая синхронизация произойдет по расписанию
- Товары без категорий пропускаются

## Производительность

- Используется пагинация для получения больших объемов данных
- Лимит запросов: 1000 записей за раз
- Изображения скачиваются последовательно
- Дубликаты изображений не скачиваются повторно
- Синхронизация не блокирует работу сервера

## Troubleshooting

### Ошибка: MOYSKLAD_TOKEN не установлен

Добавьте токен в `.env` файл:
```env
MOYSKLAD_TOKEN=ваш_токен
```

### Изображения не скачиваются

1. Проверьте права доступа к директории `backend/uploads/products/`
2. Убедитесь, что у токена есть доступ к изображениям

### Синхронизация не запускается

1. Проверьте логи: `pm2 logs vapekhv-backend`
2. Проверьте токен МойСклад
3. Убедитесь, что cron запущен

### Товары не синхронизируются

1. Убедитесь, что товары не архивированы в МойСклад
2. Проверьте наличие категорий для товаров
3. Посмотрите логи ошибок
